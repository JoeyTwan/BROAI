# BRO AI - 技术架构文档

## 1. 系统架构概述

BRO AI采用前后端分离的架构设计，前端负责用户界面和交互，后端负责业务逻辑和AI服务集成。系统基于RESTful API进行通信，实现了高内聚、低耦合的模块化设计。

## 4. 接口设计

### 4.1 认证相关接口

#### 4.1.1 用户注册

- **URL**：`POST /api/auth/register`
- **请求体**：
  ```json
  {
    "email": "user@example.com",
    "password": "password123"
  }
  ```
- **响应**：
  ```json
  {
    "token": "jwt-token",
    "user": { "id": 1, "email": "user@example.com" }
  }
  ```

#### 4.1.2 用户登录

- **URL**：`POST /api/auth/login`
- **请求体**：
  ```json
  {
    "email": "user@example.com",
    "password": "password123"
  }
  ```
- **响应**：
  ```json
  {
    "token": "jwt-token",
    "user": { "id": 1, "email": "user@example.com" }
  ```

## 5. 数据流程

### 5.1 用户认证流程

1. 用户在前端输入邮箱和密码
2. 前端发送POST请求到`/api/auth/register`或`/api/auth/login`
3. 后端验证用户信息，生成JWT令牌
4. 后端返回JWT令牌和用户信息
5. 前端存储JWT令牌到localStorage
6. 后续请求携带JWT令牌，通过Authorization头传递
7. 后端中间件验证JWT令牌，提取用户信息
8. 后端处理请求，返回响应

### 5.2 AI聊天流程

1. 用户在前端输入消息，点击发送
2. 前端检查用户是否登录，未登录则弹出登录对话框
3. 前端检查用户每日用量，超出限制则提示用户
4. 前端发送POST请求到`/api/ai/chat`，携带消息历史
5. 后端中间件验证JWT令牌和用量限制
6. 后端调用AI服务API，发送消息历史
7. AI服务返回流式响应
8. 后端将AI响应流式返回给前端
9. 前端以打字机效果显示AI回复
10. 后端异步记录API调用日志

### 5.3 会话管理流程

1. 用户在前端创建新会话
2. 前端发送POST请求到`/api/conversations`
3. 后端创建会话记录，返回会话信息
4. 用户发送消息，前端更新本地会话状态
5. 前端定期同步会话到后端`/api/conversations/sync`
6. 用户重命名或删除会话，前端发送PUT或DELETE请求
7. 后端更新会话记录，返回更新后的信息
8. 前端更新本地会话状态

## 7. 关键技术实现

### 7.1 AI集成

#### 7.1.1 流式输出

- **实现方式**：使用Server-Sent Events (SSE) 或HTTP/2 Server Push
- **技术细节**：
  - 后端使用Express的response.write()方法逐块发送数据
  - 前端使用EventSource API接收流式数据
  - 实现打字机效果，逐字符显示AI回复

#### 7.1.2 用量限制

- **实现方式**：基于用户ID和日期的用量计数
- **技术细节**：
  - 每次AI调用前检查用户今日用量
  - 超出限制则返回429错误
  - 每日00:00自动重置用量
  - 使用定时任务确保重置操作的可靠性

### 7.2 认证机制

#### 7.2.1 JWT实现

- **实现方式**：使用jsonwebtoken库生成和验证JWT令牌
- **技术细节**：
  - 令牌包含用户ID和邮箱
  - 令牌过期时间为7天
  - 刷新令牌机制（可选）
  - 密码使用bcrypt加密存储

#### 7.2.2 CORS配置

- **实现方式**：使用cors中间件配置CORS策略
- **技术细节**：
  - 允许来自客户端域名的请求
  - 开发环境允许所有域名
  - 配置允许的HTTP方法和头部
  - 支持credentials

### 7.3 会话管理

#### 7.3.1 本地存储

- **实现方式**：使用localStorage存储会话数据
- **技术细节**：
  - 会话数据包括ID、标题、创建时间和消息列表
  - 登录后自动同步到服务器
  - 定期自动同步，避免数据丢失

#### 7.3.2 会话同步

- **实现方式**：使用防抖机制，延迟同步会话数据
- **技术细节**：
  - 消息发送后延迟2秒同步
  - 批量同步会话数据，减少API调用
  - 处理冲突情况（如同时在多个设备上修改同一会话）

### 7.4 错误处理

#### 7.4.1 前端错误处理

- **实现方式**：使用try-catch和错误边界
- **技术细节**：
  - 捕获API请求错误
  - 显示友好的错误提示
  - 处理网络错误和超时
  - 提供重试机制

#### 7.4.2 后端错误处理

- **实现方式**：使用Express错误中间件
- **技术细节**：
  - 统一错误格式
  - 开发环境显示详细错误信息
  - 生产环境显示通用错误信息
  - 记录详细错误日志
  - 分类错误类型，返回不同的HTTP状态码

## 8. 安全设计

### 8.1 数据安全

- **密码加密**：使用bcrypt加密存储密码，支持自适应哈希
- **敏感数据保护**：敏感配置信息通过环境变量管理，不硬编码到代码中
- **数据传输加密**：使用HTTPS加密传输数据
- **数据库访问控制**：使用最小权限原则，限制数据库用户权限

### 8.2 API安全

- **认证机制**：所有API调用使用JWT令牌认证
- **授权机制**：基于用户角色的访问控制
- **速率限制**：防止API滥用
- **输入验证**：验证所有API输入，防止注入攻击
- **输出编码**：对API输出进行编码，防止XSS攻击

### 8.3 应用安全

- **安全头设置**：使用helmet中间件设置安全头
- **CORS策略**：严格配置CORS策略，只允许信任的域名访问
- **依赖管理**：定期更新依赖，修复安全漏洞
- **代码审查**：定期进行代码审查，发现安全问题
